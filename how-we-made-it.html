How we made Bangers and Smash!

Partly a guide for anyone who wants to try making a browser game, and partly a notebook so I remember how we did it.

Start simple

We started with a basic GitHub repository and asked AI to help us create a simple driving game inspired by the games we loved: Stunt Car Racer, Driver and the crash-heavy spirit of Wreckfest. The important rule from the start was that everything had to run directly in a web browser.

Make the first car

I took a few photos of a toy model of the orange muscle car I had at home and put the images into Meshy to create a 3D model. That gave us something recognisable and fun to drive while the game was still very rough.

Shrink it for the web

I downloaded the model as a GLB and ran it through SHRINK3D, another little app we built to reduce 3D models for games and 3D printing. We then asked AI to help wire that smaller GLB into the game. Keeping the models small matters because every car has to download and run in the browser.

Play it as early as possible

Once there was a simple working game, we stopped polishing and played it. We sent it to friends, they had a laugh crashing around, and—more importantly—they started sending us photos of cars they wanted to see in the game. That told us the idea had some life in it.

Add multiplayer

Next came multiplayer. Again, the rule was: no installation and no special app. Create a room, send a link or code to a friend, and play in the browser. We tested it the same way we had tested the first version—with real people rather than trying to predict every problem ourselves.

Turn friends' cars into game cars

We added more vehicles, mostly from friends and family. The 1970s Saloon started from my brother Paul's old Ford Escort, the German Beema came from Dom's BMW, and the Happy Camper is based on my own old VW campervan—which is sitting on my drive as I write this. Each one starts with photos, becomes a 3D model, gets reduced for the web, then is fitted into the same game system.

Tune the physics

Adding the model is only half the job. We then adjusted the physics so the cars feel different: weight, wheelbase, grip, steering, suspension, torque, stability and damage all change the character. It is not meant to be a perfect engineering simulation; the aim is that every vehicle feels believable and, most of all, fun.

Build a track editor

Once we had cars worth driving, we added a track editor so we could quickly make new circuits, hills, jumps and overpasses without hand-coding every track. Then we added barrels and chickens, because sensible development plans only get you so far.

What comes next?

It is now fairly easy for us to add a new car, but the next challenge is to make it easy for players to add their own vehicles. Ideally you will be able to bring your own favourite car into the game without touching the code. Watch this space.

What we learned

You do not need to begin with a giant design document or a finished 3D pipeline. Start with one thing that works, put it in front of people, laugh at what breaks, fix it, and then add the next thing. GitHub gave us somewhere to keep the project, browser technology meant anyone could try it, and AI helped us move quickly between an idea and something playable.

Happy gaming—and drive safely.
